Environment check

Answers one question - is my setup going to work? - before the course depends on the answer.

There are two halves, and you want both. Part 1 runs right here and checks that your browser can run the interactive parts of the site. Part 2 is a notebook you download and run in Jupyter; it checks the machine you will actually do the work on, which is the one that usually has the problem.

Nothing here changes anything. No installers, no repair buttons, nothing written to your computer. Both halves only look and report. If something is wrong, you get a short description you can send me.

Boots the same Python-in-the-browser engine the module pages and simulations use, then runs one real calculation through it.

2. Your own machine

  
This half is a Jupyter notebook called
  DTSC520_Environment_Check.ipynb. It is about 40 lines of Python
  that look at your setup and print a summary - it is not an assignment, there
  is nothing to submit, and you can delete it afterwards.

  2. Open it in Jupyter the way you open any notebook.

It checks the things that actually go wrong on this course:


  
    
    
  1. Your Python version, and whether Jupyter is running the interpreter you
      think it is - two Pythons on one machine is the classic invisible fault.
    2. 
    
  2. numpy and pandas import, with versions.
    3. 
    
  3. A read_csv from a relative path succeeds. This is
      the working-directory problem Module 4 teaches, and it is the first thing
      that really breaks - it shows up as a missing-file error when the file is
      not missing.
    4. 
    
  4. Plots draw inline, which Module 5 needs.
    5. 
    
  5. Cell magics register, so the %%expect cells behave.
    6. 
  


  
If numpy, pandas or matplotlib are
  missing, that is not a failure - Module 2 is pure Python and
  the rest arrive later. The notebook says so, and then gives you the exact
  command to install them anyway, because there is no reason to wait and every
  reason not to be doing it the night an assignment is due.


  
It works out the right command for your setup - %pip
  or %conda - and uses the notebook form rather than a terminal
  one. That matters: plain pip install in a terminal installs into
  whichever Python comes first on your PATH, which on a machine with two
  Pythons is often not the one Jupyter is running. That is the exact fault the
  notebook checks for a few lines earlier.
